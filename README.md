# JPWord Remix

JPWord Remix 是一个面向 `.jpwabc` 的本地工具，目标不是复刻完整 JP-Word，而是补上它在实际使用中最缺的两件事：

1. 旧版 JP-Word 不能直接把“指定声部组合”导出成 MP3、MIDI、MusicXML 等文件。
2. 旧版 JP-Word 不能方便地单独调每个音轨/声部的音量。

这个项目就是围绕这两个问题做的，所以重点一直是“按声部选择播放与导出”，而不是完整还原 JPW 的全部排版和记谱语义。

## 现在能做什么

- 导入 UTF-16 LE 编码的 `.jpwabc` 文件
- 从 `.Voice` 段重建 1 到 4 个声部的时间线事件
- 任意勾选声部组合进行试听
- 分别调整每个声部的音量
- 分别调整每个声部的乐器
- 导出当前选中声部组合为 MIDI
- 导出当前选中声部组合为 MusicXML
- 导出当前选中声部组合为 MP3
- 打包为本地可直接运行的 Windows EXE

## 为什么不是完整 JPW 解析器

JP-Word 的格式和版面逻辑很复杂。这个仓库当前只实现了一个“能解决导出与声部控制问题”的实用子集。

要明确的一点是：

- 这里解析的是可播放事件，不是完整排版对象模型。
- 它适合把特定写法的 `.jpwabc` 转成可播放、可导出的声部时间线。
- 它目前不承诺支持所有 JPW 语法，也不承诺完整还原所有反复、房子、跳转、复杂版式语义。

## 当前稳定支持的谱例写法

当前版本主要面向像“飞云之下”这种示例风格的谱子，已经明确验证过这类文件可以正常识别与导出。

现阶段建议满足这些条件：

- 每一行按固定节奏排布，常见情况是每行 4 个小节
- 没有复杂反复记号
- 没有房子记号
- 没有 D.C.、D.S.、Coda 一类跳转逻辑
- `.Voice` 段中的音符都带有 `{C:...}` 时值信息

换句话说，这个仓库目前适合“按时间线直接展开”的 JPW-ABC 写法，不适合所有复杂总谱工程。

## 当前支持的音符子集

下面这些现在已经做了兼容：

- 休止和普通数字音符：`0` 到 `7`
- 升降号：`#5`、`b7`
- 八度记号：`5'`、`5,`、`g5`、`d5`
- 时值修饰：`_`、`-`、`.`
- 连音括号
- 带修饰信息的时值标记，例如：
	- `{C:2.5}`
	- `{C:2.5,None}`
	- `{C:2.5,Other}`
	- `{C:2.5(1.2,1.3,0)}`
	- `{C:2.5(1.2,1.3,0),None}`
	- `{C:0,All,Unconnect}`

项目当前就是依赖这些标记，从 `.Voice` 段重建声部时间线。

## 示例文件

仓库包含一个已经验证过的四声部示例：

- `examples/飞云之下-四人合唱-草稿.jpwabc`

这个示例适合用来验证：

- 四声部识别
- 选择部分声部播放
- 导出指定声部组合为 MP3 / MIDI / MusicXML
- 单独调某个声部音量后的试听结果

## 一个最小格式示意

下面只是说明当前解析器关注的核心结构，不代表完整 JPW-ABC 语法：

```text
.Voice
|{C:0} 3{C:1.5} 5_{C:0.75} #5{C:1,None} b7.{C:1.5,Other}
$
```

当前实现主要关心的是：

- `.Voice` 段
- 小节分隔
- 音符 token
- `{C:...}` 时值信息
- 声部分块

## 说明

- 当前版本直接从 `.Voice` 段重建音符事件，不依赖原 JP-Word exe。
- 调号使用 `KeyAndMeters = {1=...,x/y}` 中的主音和拍号信息。
- BPM 若文件内未提供显式速度字段，则默认使用 88 BPM。
- MusicXML 当前更接近“事件导出”，适合作为继续整理和换谱的中间格式。
- 这个项目当前是“解决指定声部导出和单声部音量控制”的实用工具，不是完整 JPW 兼容层。
